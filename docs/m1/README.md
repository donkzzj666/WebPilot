## 第四组：完成调度、动作、证据与判定（顺序 11–15）

- [ ] **11｜M1-10 实现持久队列与统一资源租约**
  
  **前置：** M1-03、M1-08。  
  **交付：** Worker 单实例保护、领取与心跳、epoch、固定顺序取锁，以及活跃槽、站点账号、仓库、环境、上下文资源管理。  
  **勾选条件：** 竞争 Worker、第三个活跃项、第五个上下文、账号／仓库冲突、新增资源和过期租约验证通过；最多两项活跃、四个存活上下文；写入串行、无死锁、旧执行资格失效；未知写入隔离和接管占用不会随短租约自动释放。

- [ ] **12｜M1-11 实现统一预算、配额和独立截止控制**
  
  **前置：** M1-10。  
  **交付：** 首次开始与资源／扣额同事务，UTC 存储及上海切日，动作、页面、活跃时间、恢复、站点节奏、CI 和接管预算；单调时钟、持久心跳和独立截止取消器。  
  **勾选条件：** 覆盖 150/151 动作、25/26 内容页、3/4 次同阻碍恢复、普通 42/43 次、总额 50/51 次、跨日、20 分钟、3 秒间隔与挂起等待；心跳间强杀后时间不回退、不漏计。公开每日 50 次、监控预留 8 次；续跑不重复扣额，新 Run 扣额；失败派发及重新打开页面计数；冷却释放槽但计活跃预算，暂停／排队／接管等待不计，CI 等待累计最多 20 分钟。

- [ ] **13｜M1-13 实现结构化浏览器动作网关**
  
  **前置：** M1-10、M1-11、M1-12。  
  **交付：** 允许动作集、语义定位／DOM／截图坐标退路、观察快照、审计和持久动作意图；派发前核对 epoch、控制权、权限和预算。  
  **勾选条件：** 过期 epoch、旧截图、换帧／标签、页面变化、越界目标及超时验证通过；不执行任意 JS/Shell/HTTP/SQL；十个原子动作计十次，默认动作超时 30 秒；写动作仅在夹具验证。

- [ ] **14｜M1-14 实现证据工件、脱敏和受控读取**
  
  **前置：** M1-02、M1-08、M1-12。  
  **交付：** 工件元数据、临时写入／校验／原子重命名／索引提交、不可变哈希、原件与展示副本、模型输入过滤、受控读取 API。  
  **勾选条件：** 半写中断、重命名后数据库失败、损坏、磁盘满、路径穿越及伪造密钥过滤验证通过；工件不覆盖、孤儿可登记清理，磁盘满停止新动作，敏感原件不直接导出，缺证据不能成功。

- [ ] **15｜M1-15 实现运行时验证器和成功聚合器**
  
  **前置：** M1-05、M1-14、M0-02。  
  **交付：** 规则验证、独立语义调用上下文、四种检查结论、字段级证据关联、成功／部分／失败聚合和人工参与标记。  
  **勾选条件：** 缺证据、关键字段错误、冲突、未知写入、越权、非关键缺失及全通过样例均验证；仅关键条件全部 PASS、证据完整、无未决写入和关键副作用才成功；验证器无写权限、不接收执行器自评、不修改规则。

## 第五组：串联循环并完成恢复与控制（顺序 16–20）

- [ ] **16｜M1-16 用 LangGraph 串联观察—决策—动作—验证循环**

- [ ] **17｜M1-17 集成两类检查点和只读崩溃恢复**

  **勾选条件：** 模型调用、页面动作、证据保存及业务／图提交边界故障通过，覆盖浏览器存活／关闭、身份／对象变化与版本／事件失配（FR-02）；恢复先核对，不重放最后点击、不重复记账、不清零预算、不覆盖业务账本；人工控制未交还不操作，未确认写入交 M1-23 查证。

- [ ] **18｜M1-18 实现暂停、继续、取消与关联重跑**
  
  **前置：** M1-17、M1-04。  
  **交付：** 操作 API、异步完成事件、interrupt/resume 与持久等待；暂停保留会话／账号占用、退出图调用并释放活跃槽；重跑使用新 Run/thread 并关联原副作用。  
  **勾选条件：** 各非终态取消、动作中暂停、重复请求、终态恢复拒绝及落库／图中断间崩溃验证通过；202 仅表示受理，停止新动作后处理在途动作；恢复先核对，同 thread 不并发续跑，重入不重复副作用，重跑重新扣额；CI／接管等待暂用夹具覆盖，完成 FR-04 的暂停／取消部分。

- [ ] **19｜M1-23 实现写入意图与 UNKNOWN 查证协议**
  
  **前置：** M1-13、M1-17、M1-18、M1-14。  
  **交付：** 稳定业务操作键、四态写入记录、查证适配接口，以及重启、取消、重跑隔离规则；使用测试站模拟外部写入。  
  **勾选条件：** 意图落库后中断、已写入但回执未存、节点重入、新 Run 重试及查证中对象变化均覆盖（FR-03）；已发生则复用，确定未发生且身份／目标／前提一致才重试；UNKNOWN 不重放并阻塞成功，每次实际派发单独计数；epoch 不能撤回已发动作，取消不自动回滚外部数据。

- [ ] **20｜M1-19 建立日志、指标与进程健康状态**
  
  **前置：** M1-16、M1-11。  
  **交付：** 关联 ID、thread／图版本／节点／checkpoint 诊断、错误类别、动作／时间／模型用量、队列／恢复／未知写入指标，以及 API/Worker 独立健康检查。  
  **勾选条件：** 成功及失败运行可追踪，配置／未配置价格均正确，测试凭据扫描通过；框架事件不能替代持久业务事件和 SSE；无价格不编金额，无内部推理、Cookie 或完整敏感提示；默认禁用外部追踪并核查出站，健康状态不等于任务成功。

## 顺序说明与阶段退出条件

- 以上顺序满足全部原始直接依赖。M1-12 提前到浏览器生命周期之后、登录联调之前；M1-23 放在恢复与取消之后，先收口未知写入协议。
- 需要并行时：M1-01 后可并行推进数据库与模型适配；M1-02 后可推进配置快照；M1-12 后，动作网关与证据模块可在各自前置齐备后并行；M1-20 可在 M1-06/07/09 完成后提前开始，M1-22 可在 M1-15/20 完成后提前开始。正式勾选仍以完整依赖与联调通过为准。
- M1-24 是 M1-25 的前置门槛。阶段退出须 25 项交付及适用验证完成，真实只读链路可复核，并保留取消、恢复和越权拒绝证据。
- M1-23 的写入只在测试站验证；真实 GitHub 写入、四类业务扩展、完整接管、记忆、WA 部署和正式评测仍按后续阶段推进。M1 完成不代表这些后续阶段已完成。
