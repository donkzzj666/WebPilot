# M1-23：写入意图与 UNKNOWN 查证协议

状态：**VERIFIED**。验收完成日期：2026-10-02（北京时间）。M1 清单进度：**19/25**。

schema v18 将语义写入意图、查证原件、逐次派发、当前 Run 引用和显式查证重跑关系持久化。稳定业务键包含任务、身份、规范化目标和预期变化摘要，不包含 Run、epoch 或模型临时操作编号。原操作编号沿用；每次实际派发仍创建独立步骤和预算尝试，历史账本不重写。

## 交付与边界

| 能力 | 实现与拒绝条件 |
| --- | --- |
| 四态记录 | INTENT、CONFIRMED、NOT_APPLIED、UNKNOWN；意图、步骤和扣额先于浏览器派发同事务提交 |
| 三分支查证 | 可信本地适配器返回 APPLIED、NOT_APPLIED 或 UNKNOWN；仅使用内部观察与受控 GET／HEAD，模型和公开 API 不能安装适配器或确认写入 |
| 原件核验 | 保存受限原始事实；核对原件字节／哈希、当前页面、身份、目标、前提、Run、Worker 和 epoch；读取原件在写事务外，事务内再核执行资格 |
| 安全重试 | NOT_APPLIED 证明限当前执行资格、60 秒、单次消费；实际在途步骤、过期／已消费证明、身份或前提变化均不能允许重试；独立动作截止和站点节奏继续生效 |
| 历史复用 | 新 Run 和图节点重入沿用业务键；历史 CONFIRMED 没有当前证明时进入只读查证，确认后复用回执；后续 UNKNOWN 不抹掉历史已发生事实 |
| 运行循环 | 未确认写入先查证，再进入 M1-17 恢复或下一次观察／决策；UNKNOWN 形成持久等待，阻止普通派发和完整成功；已有部分交付可保留 PARTIAL 并展示未决项 |
| 取消与重跑 | 取消停止新动作，保留已发动作、外部数据、预算和未决写入的隔离，不自动回滚；相同冻结契约的协议重跑使用显式 RECONCILING Run；旧会话未关闭／丢失、人工持有、活跃执行器、混合旧记录或契约变化继续阻塞 |
| 认证诊断 | `GET /v1/runs/{run_id}/write-intents?after=0&limit=100` 提供任务级分页状态、历史来源和计数；不返回回执正文、原件路径、凭据或执行 Token，不提供状态改写入口 |

旧 epoch INTENT 经当前有效 APPLIED 原件核实后，可作为已解决历史保留，允许后续不同写入；当前 epoch 的实际在途步骤仍阻塞。历史解决不因换页或缓存期限撤销，当前业务操作的回执复用仍要求新的有效证明。

## 验证中发现的问题与修复

失败证据均保留，未将失败入口改记为通过，未继续实施 M1-19 等后续任务。

| 问题 | 修复 |
| --- | --- |
| 历史 schema 没有协议表 | 恢复与会话边界检查表是否存在，保留 v12／v13／v17 的原隔离行为 |
| 排队原因约束拒绝新字符串 | 队列继续使用已有 `resource_conflict` 原因，Run 诊断保留 `unknown_write`，未修改历史 SQL |
| 独立截止测试包装器签名滞后 | 包装器透传新增的内部只读查证参数，原 0.04 秒截止保持不变；单文件验证使用实际 storage 包导入 |
| 状态矩阵绕过查证重跑绑定 | QUEUED→RECONCILING 必须有显式协议关系；测试断言未经绑定的转移被拒绝，SQL18 守卫不放宽 |
| 只读查证紧随导航触发站点节奏 | 查询在原动作预算和独立截止内等待实际可用节奏，再使用同一次计数的 GET；普通探针导航也等待真实节奏，不清零或返还预算 |
| 暂停与继续请求之间的 saver 竞态 | 后来的 `operation_requested` 使通用“最新事件”投影丢失暂停 progress，重复收尾写坏图锚；专用控制加载器在单一 SQLite 快照中绑定精确 APPLIED 回执、首个 wait_registered 和对应 progress，只允许实际 PENDING 控制请求尾部；新业务事件、重复 wait、实际状态推进或版本变化均拒绝；M1-17 恢复检查保持不变 |

暂停修复新增 8 个确定性回归，包括首次保存前已收到继续请求、保存后重复收尾、真实 AsyncSqliteSaver 不重写原锚，以及跨语句并发继续仍读取一致快照。相关 16 个测试文件 **361 项全部通过**。
