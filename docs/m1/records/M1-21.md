# M1-21：执行工作台与实时进度

状态：**VERIFIED**。2026-10-02（北京时间）。最终源码、实际界面、全新安装回归和数据保护核验全部通过；M1 已完成 **22/25**，M1-22／24／25 保持 TODO。

本项复用 schema v18、运行控制、预算、图检查点与证据协议，无新增迁移或依赖。选择或创建任务不会自动启动；启动及暂停／继续／取消均要求核对目标并明确确认。接口和使用方式见[工作台开发说明](../../development/workbench.md)。

## 交付

| 能力 | 行为 |
| --- | --- |
| 执行快照 | 一次有界 SQLite 只读事务投影当前 Run、版本、冻结条件、检查点子目标、已验证项、预算、队列原因、页面头及最近事件 |
| 实时进度 | SSE 触发权威 API 重读；没有业务事件的图阶段与剩余时间通过定时快照更新，显示最近持久化阶段与时间 |
| 事件恢复 | 64 位 ID 保留十进制字符串；重复去重，冲突／乱序重同步，正常全局 ID 间隙允许；断线／超时／异常锁住控制并重连、分页重放 |
| 控制收据 | 202 仅受理，PENDING 显示处理中；查询持久 APPLIED／REJECTED 回执，再读取 Run 状态；提示随最新回执更新 |
| 版本与幂等 | 控制绑定任务／Run 及冻结版本；409 重读后重新确认，未知请求保留同一正文与键先查询；切换任务立即禁用旧任务控制 |
| 页面证据 | 显示受管快照 ID、时间和有效性；认证读取关联过滤文本／截图衍生工件，错误明确显示；不暴露原 DOM、私有路径或内部推理 |
| 界面联动 | 任务卡选择当前任务；控制后的实际状态与版本刷新任务入口；桌面及 375px 手机布局可用 |

新增 `GET /v1/tasks/{task_id}/workspace` 与 `GET /v1/runs/{run_id}/events`，沿用本机鉴权、origin 边界和 no-store。历史 Run 查询必须属于任务，当前 UI 操作当前 Run。投影不建库、迁移、领取任务、结算预算或触发恢复；旧记录缺配置快照时设置版本为 0，界面禁用控制。

工作区 v4 与最终新环境各通过相同 21 项验收。每轮使用 4 个实际 Worker、3 次自有模型 HTTP 调用、1 次实际浏览器读取点击、7 次显式控制和 11 次流连接。暂停等待在途读取结束，继续沿用同一 Run／冻结配置并核验条件，没有重复点击；实际导航消耗动作预算并拒绝下一动作，最终 FAILED；取消在真实图边界收敛，不显示成功。过滤文本实际通过认证内容 GET 读取并绑定 Run／快照，派发动作使页面头失效的状态也被正确显示。

READY 准备与站点门控是明确的受约束数据库夹具；门控之后由真实 Scheduler 返回排队原因且模型调用为 0。重复／冲突／乱序／3 次强制断线只改变传输层，持久事件账本未修改；正常 ID 间隙来自另一个专用任务。截图工件分支有契约与受控读取校验；本次实际工作台读取的是过滤文本，不声称验证了原网页截图。工作台不实现 M1-22 结果页，也不替代 M1-25 的公开只读业务闭环。

桌面及 375px 手机产品 UI 截图已检查，手机无横向溢出。每轮 42 个公开验收文件扫描 3 类合成敏感标记通过。全部自有 Worker 退出码为 0，API／前端／浏览器退出后再核验数据库与哈希；两库完整性与外键检查通过，活动 Worker／浏览器会话为 0，写入意图为 0。使用自有 HTTP 模型／页面及内存凭据，没有付费模型、真实账号、真实 GitHub 写入或保留评测真值访问。

默认 API／Worker／前端未因验收重启，默认两库未迁移。三份既有活动日志基线前缀及完整哈希一致，无追加；M1-17／18／19／20／23 的受保护资料及旧结论保留原件。

## 失败历史与修复

| 问题 | 修复与结论 |
| --- | --- |
| v1 探针要求在途动作页面头仍有效 | 派发前使旧头失效属于网关正确行为；改为核验快照绑定、失效状态与关联证据，原 false 报告保留 |
| v1 运行期间前端修复改变 3 个冻结文件 | 原源码状态报告保持 false，不用于最终结论；重新冻结 v2／v3／v4 |
| v2 取消任务被事件间隙夹具加入历史 Run | ControlStore 正确拒绝重复启动；将间隙 Run 移到专用任务，增加真实 ControlStore 隔离回归；原 false 报告保留 |
| 审阅发现任务切换与其他客户端回执问题 | 立即绑定所选任务，提交再校验目标；优先展示最新持久操作，校验冻结字段与不可变请求对象 |
| v3 通过后视觉检查发现提示停留“等待” | 提示派生自最新持久回执，增加状态转换与实际 DOM 检查；v4 21 项通过 |
| 旧 v3 新环境运行被最终修复取代 | 仅中断已核实的自有进程组，退出 130，保留取消报告及已完成子报告；不作为全新安装通过证据。最终 v4 从头完整回归通过 |

失败报告未改写为通过，中间 v3 的通过仅适用于当时源码。最终结论只使用 v4 冻结与最终新环境，没有执行后续子任务。
