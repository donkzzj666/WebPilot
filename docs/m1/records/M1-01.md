## 出站验证的事实与限制

应用入口在导入框架前覆盖关闭 LangSmith/LangChain 的 `TRACING`、`TRACING_V2` 和旧 handler 开关。默认开关之外，实际集成记录 Python socket 事件、Playwright Node driver 的 net/dns/dgram 调用和 Chromium NetLog，使用已知回环连接确认审计路径有效。

有界面 Chromium 即使设置关闭后台联网的标志，仍会提出 Google 后台服务请求；初始未隔离运行已记录这一事实，没有作为通过证据。最终测试浏览器使用固定本机代理：只返回指定夹具，拒绝其他目标和 CONNECT，完全没有上游转发代码；测试 DNS 映射到回环地址。[原始请求及拒绝记录](../../../artifacts/verification/M1-01/clean-install-20260929T041700.404891Z/check-20260929T041732Z.PXZmez/integration/fixture-http-requests.json)、[网络审计结果](../../../artifacts/verification/M1-01/clean-install-20260929T041700.404891Z/check-20260929T041732Z.PXZmez/integration/network-summary.json)。

Chromium 对 `2001:4860:4860::8888:443` 的 IPv6 可达性套接字探测单列。分类要求精确目的地址、关联祖先的可达性事件、完整 socket 关闭且没有任何 UDP 收发或未知事件；实际 UDP 发送、无法归属的 UDP 发送以及 TCP/DNS 越界均继续失败。该解释由 [153.0.8010.12 对应源码](https://raw.githubusercontent.com/chromium/chromium/153.0.8010.12/net/dns/host_resolver_manager.cc) 的 ConnectAsync/GetLocalAddress 路径支持。

通过结论仅为：在本次隔离夹具配置及已观察接口范围内，没有未授权遥测外联或外部应用数据传输。不是系统层零包声明，也不是 M1-12 产品网络边界验收。M1-08/12 接入真实网站前必须处理浏览器后台请求和替代通道。
