# M1-15 验证记录：运行时验证器和成功聚合器

状态：**VERIFIED**。M1 当前完成进度 **15/25**（M1-01～M1-15）。完成日期：2026-10-01（Asia/Shanghai）。依赖 M1-05、M1-14、M0-02；依据总任务清单 M1-15、TRD §3.4、§6.1。

## 交付范围

- schema v14 显式追加不可变 `run_verifications`、`run_results`；契约、候选、字段关联、证据摘要和 Run 版本共同绑定验证记录。
- 规则核心只接收冻结 DTO，逐字段读取原始 JSON Pointer 事实，输出 `PASS / FAIL / INSUFFICIENT / CONFLICT`。覆盖财务 Decimal／期间、代码仓库／文件／精确 SHA 与 CI、Grafana 范围、研究来源／截止、监测源类别／真实读取计数与连续边界。
- 独立语义调用仅接收固定规则、待核实事实和脱敏原文；排除执行器历史、自评与动作工具。沿用原 Run 模型预算和冻结配置，使用独立提示词版本；模型 PASS 不能覆盖程序失败、冲突或字段不足。
- 可信聚合器重读实际工件、执行资格、整个 Task 的副作用和人工参与数，生成成功、部分或失败。当前／历史 UNKNOWN、未决动作、越权、未核实回执及缺口不能被隐藏。
- 结果、终态、资源释放与 `result_ready` 事件同事务提交。并发／重复终结只有一份结果；完整应用契约不能通过直接状态服务、Scheduler.finish 或 SQL 绕过聚合器。
- `GET /v1/runs/{run_id}/result` 提供本机认证后的结果、逐字段检查和自主／辅助标记；没有公开写入判定或指定 outcome 的接口。

接口及初学者说明见[运行时验证开发说明](../../development/verification.md)。

## 验收修正

原始 JSON 重复键会被默认解析器取最后一个值，现明确拒绝歧义、截断和非有限数值。财务计算使用独立且有界的 Decimal 精度上下文，避免默认 28 位精度造成舍入伪匹配；期间未冻结明确为不足，不推测日期。

CONFIRMED 副作用不能只凭非空回执和任意可读工件通过，还须在当前原件中核对操作、目标、回执和身份。语义未通过的研究条目不会算作可信局部交付。提交前再次核验租约时效，避免完整性读取过慢后继续使用过期资格。

首轮完整回归中一项旧测试仍期待语义 PASS 覆盖字段不足，已同步为保持 INSUFFICIENT／FAILED，并通过后续回归。第一次全新安装的 2699 项组件测试通过，但旧网关探针在 iframe 尚未完成加载时固定快照，被正常的快照保护拒绝；探针已增加 load 等待后再观察，第二次全新安装全部通过。产品快照保护未放宽。早期失败的探针和日志保留，没有覆盖成成功记录。

## 适用边界

本项提供运行时验证和结果聚合，不包含 M1-16 执行图、正式站点适配器或完整产品结果页。Worker 仍为 `task_execution_enabled=false`。当前字段解析支持明确的结构化原件定位；PDF、截图、未知规则和任意财务公式等未支持的事实保留不足，不能仅凭文件存在或模型自评通过。

本次验收不重启默认用户服务、不迁移默认数据、不推送 Git。启动新版服务时才应用 schema v14。源文件快照：[m1-15-source-manifest.json](../../../config/m1-15-source-manifest.json)。验收汇总：[report.json](../../../artifacts/verification/M1-15/report.json)。清单和完成标记已更新。
