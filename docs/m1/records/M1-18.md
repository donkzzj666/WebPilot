# M1-18：暂停、继续、取消与关联重跑

状态：**VERIFIED**。复验完成日期：2026-10-02（北京时间）。M1 清单进度：**18/25**。

schema v17 保存启动、暂停、继续、取消、关联重跑的持久请求和完成回执。公开 API 核对认证、幂等键及契约／状态／设置版本；202 仅表示 PENDING 受理，APPLIED／REJECTED 通过独立事务与持久事件表示实际完成。

控制受理后停止新派发，在途动作保存真实结果；Worker 在安全边界处理请求。暂停保留会话／账号占用并释放活跃槽，继续同一 Run/thread 前经过 M1-17 查证。重跑创建新 Run/thread 和预算，保留原运行与副作用引用。UNKNOWN、人工控制权和原失败记录均不能被普通继续或重跑清除。

## 失败原因与修复

首次正式验收在 2026-10-01 以 **2026 通过、1 失败**中断，后续任务没有开始。2026-10-02 用户要求检查、修改并重新验证后，逐步发现并修复下列问题。本轮修改仅涉及测试、验收探针及记录，业务实现和数据库约束未放宽。

| 问题 | 原因与修复 |
| --- | --- |
| 预算准入断言 `KeyError` | 调度资格返回 `run_state_version`，测试误用 `state_version`；改为实际字段 |
| 旧图版本取消夹具被拒绝 | 夹具在创建 Run 后修改不可变图版本；改为创建时模拟旧版本，保留不可变约束 |
| 历史迁移断言失败 | v15→v16 测试默认迁移至最新 v17；升级和重复执行都明确指定 `target=16` |
| 浏览器启动检查超时 | 探针仍等待旧文案“任务执行未开放”；改为当前“任务界面待接入” |
| 崩溃探针错误被覆盖 | 清理 SIGSTOP Worker 时发生 PermissionError，覆盖首个错误；现在保留原始异常链和清理错误，逐资源清理，仅向当前已确认身份的子进程组发信号，不扫描历史 PID |
| 崩溃窗口读取顺序 | 先真实 SIGKILL 并等待 Worker 退出，再读取已提交账本；记录 `observed_after_sigkill`，验证业务等待在崩溃后保留，避免暂停全部线程时读取可能被冻结的 SQLite 写锁 |

旧崩溃报告没有保留首个异常，不能据此断言当时一定是 SQLite 锁超时。修正后的真实探针在工作区和干净环境中均通过 58 项检查。新增 4 个辅助回归用例覆盖读取顺序、组身份／权限错误清理以及原始错误保留；辅助测试最终 19 项通过，并已纳入最终 3069 项完整测试。

源码一致性核对另修正了审计脚本对 Finder `.DS_Store` 的分类；它属于安装脚本明确排除的本地元数据，不是执行源码。该次审计失败也保留在复验目录。
