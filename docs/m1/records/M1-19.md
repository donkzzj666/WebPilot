# M1-19：日志、指标与进程健康状态

状态：**VERIFIED**。验收日期：2026-10-02（北京时间）。M1 已完成 **20/25**；M1-20／21／22／24／25 保持 TODO，本次未实施后续任务。

schema 仍为 v18。复用既有事件、步骤、模型、预算、队列、恢复和写入账本，建立本地诊断；没有新增 SQL 迁移或依赖。

## 交付与边界

| 能力 | 实现 |
| --- | --- |
| 本地结构化日志 | API／Worker JSONL，固定元数据字段及错误枚举；0600 文件、有界轮转、跨进程锁与短等待；异常和拒收不改变业务结果 |
| 请求关联 | 每次 HTTP 独立 transport UUID；任务幂等响应保留原业务 request ID；已提交 task／run／operation／event 引用绑定到日志 |
| 可信框架诊断 | 节点和真实 saver 的 thread／图版本／checkpoint，与持久事件、进度、步骤及验证引用核对；同步保存后在下一节点入口记录真实历史检查点，保留 finally 诊断 |
| 只读诊断 | `/v1/diagnostics/runs/{run_id}` 的事件与模型双游标，分页和资源上限；单一 SQLite 读快照，不返回正文、URL、提示词、凭据、原始异常或私有原件 |
| 持久指标 | 动作、已结算时间、模型用量；当前队列年龄／首次领取耗时与业务等待分开；恢复预算次数与回执阶段分开；UNKNOWN、隔离和证据状态；未实现指标明确标记 |
| 静态价格 | 严格十进制 token 价目生成内容版本，随设置和 Run 冻结；模型及独立语义调用保存精确估算与币种；缺价格／缺用量保持 null，分版本及币种汇总 |
| 独立健康 | `/health` 验证 API 及本机存储；`/v1/health/worker` 读取最新持久心跳租约；健康不表示任务成功 |
| 日志与出站边界 | CLI 安装不格式化消息／参数／traceback 的标准日志处理器；Uvicorn 原始访问日志关闭；导入框架前禁用继承的外部 tracing 标志，实际出站另由探针核验 |

上述接口经过已有本机认证与来源防护。框架诊断不写入 `task_events`，业务 SSE 继续只重放已提交事件。只读观测不能创建缺失业务库、结算预算、改变执行资格、清除 UNKNOWN 或安装写入适配器。Worker 健康表示持久租约有效，不是即时进程探测或任务成功证明。

实际失败调用有两种已验证退出：工作区 v5 确实捕获 `CancelledError`，最终干净环境正常返回。两者均为持久 FAILED v2／queue FINISHED，真实 saver 保留 v1／event 11／progress 18／completed=false。历史锚不被包装为终态检查点，也不改变预算截止、取消传播、恢复规则或业务事件。

出站证据每轮包含 8 个 Python socket API 事件、2 个 Node driver 事件、516 个 Chromium 审计事件、3 个代理允许事件与 2 个认证挑战拒绝；本次采集范围内外部框架 trace 连接为 0。Node 使用管道，只观察到审计加载／退出；Chromium 的非回环 IPv6 路由探测单独归类；代理认证挑战不能充当外部流量拦截证明。该结果不是系统级零数据包声明。

额外 recovery／UNKNOWN／隔离计数来自明确标注的账本夹具，不表示只读图执行了真实网站写入。任务准备重放另建无 Run 的准备任务，不调用模型或浏览器。全部验收使用自有页面、合成价目与凭据，未使用真实账号、付费模型、真实 GitHub 写入或保留评测答案。

## 失败历史与修复

| 问题 | 修复与验证 |
| --- | --- |
| 幂等响应的业务 ID 被每次请求 ID 覆盖 | 保留持久 `X-Request-ID`，增加独立 `X-Transport-Request-ID`；500 响应也提供两个头；兼容测试及实际重放通过 |
| 初次并发创建日志锁文件 | 对 macOS 同一目录 FD 的 ENOENT 查找最多重试三次，保留 NOFOLLOW 与全部文件安全判定；确定性回归及多进程检查通过 |
| 诊断连接可能创建空业务库 | 使用 mode=ro／query_only／0.1 秒 timeout 与有界 VM 工作量；缺库 node 和 saver 诊断均不创建文件 |
| 首次真实观测 v1 超时 | 两条 Run 实际已终止，但监控只登记正常返回。改为记录真实 return／exception／finally 并核对持久结算；原件未记异常类型，不把它宣称为已证实 CancelledError |
| 失败路径没有记录真实 saver | 先把只读 checkpoint 诊断移到 finally；早期 v2 观测 27 项通过 |
| 极小已知金额被聚合精度丢失 | 使用 precision 256；两种顺序的 100 位整数加 98 位小数覆盖全局及 Run 汇总，53 项观测存储／API 专项通过 |
| 首次干净安装 v3 的网关探针失败 | 3417 项测试与前端通过；网关完成 32 项后 exact-DOM snapshot 指纹复核返回 409，入口立即停止。生产网关与 M1-23 相同；探针改为完成完整 pacing、主／子 frame 及绘制就绪后观察并立即单次点击；独立及最终网关 61 项通过。原件不能确定具体 DOM／布局／焦点变化来源 |
| 第二次干净安装 v4 取消日志失败 | 3417 项测试及前端、前 17 组集成通过，观测完成 21 项后停止。真实 CancelledError 同时取消了 finally 诊断；在同步保存后的下一节点入口记录真实历史引用，保留 finally，不使用 shield／uncancel 或额外 saver 写入。114 项局部回归、77 项精确历史辅助检查及最终完整验收通过 |

首次观测、两次干净安装和更早测试入口参数／辅助函数错误均保留，失败报告没有改记为通过。最终新环境通过后才勾选本项，未执行 M1-20 等后续任务。
