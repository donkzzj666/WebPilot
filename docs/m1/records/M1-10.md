# M1-10 验证记录：持久队列与统一资源租约

状态：**VERIFIED**。M1 总进度 **11/25**（M1-01～M1-10、M1-12）。完成日期：2026-09-30（Asia/Shanghai）。依赖 M1-03、M1-08；依据总任务清单 M1-10、TRD §4.2／§9.1。

## 交付

- schema v10 追加持久队列、资源全集、递增 Worker 代次、上下文预留和不可变调度事件。既有资源租约与 UNKNOWN 隔离账本继续作为权威，v1～v9 SQL 保持原样。
- Worker 先取得本机管理器进程锁，再注册调度代次；最多两项活跃。一个 SQLite 短事务按活跃槽、站点账号、仓库、环境、上下文的固定顺序获取完整资源，失败不留下部分新锁。
- 同站点同账号和匿名站点串行，GitHub 网页编辑器共享逻辑站点；同仓库写入跨账号串行，WebArena 共用一个环境资源。
- 登录、执行、暂停、CI 等待和接管共用四个上下文名额。持久预留原子兑现为真实会话，不重复扣名额；组合延迟外键阻止绑定其他 Run 或登录会话。
- 每次授权重新检查 Worker 代次、Run 版本、epoch、期限、控制权和完整租约。退出、过期和重启撤销旧资格，保留恢复所需的逻辑占用；短租约不能清除人工控制、INTENT／UNKNOWN 或资源隔离。
- 探索新增资源前，`expand` 强制接受已提交的业务检查点。核对 Run、任务、契约、当前 epoch、最新状态事件、保存时间和已持久步骤序号后，才撤销资格、释放安全资源并整体重新排队。拒绝或事务故障保留旧状态及资源。
- 受信执行器须明确完成或进入等待；未明确释放便返回／报错时，Worker 停止派发并保留恢复状态，防止立即重派同一 Run。只读 `GET /v1/scheduler` 提供调度元数据，沿用本机 API 防护。

接口、阅读顺序和恢复边界见[调度开发说明](../../development/scheduler.md)。
