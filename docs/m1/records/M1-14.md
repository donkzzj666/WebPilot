## 验收中发现的问题

并发首次初始化曾让第二个进程看到尚未完成的控制标记；已改为先完整预分配、刷写，再无覆盖原子发布。既有标记缺失只等待正在完成的首次初始化，不会重建标记或清除故障；终态检查只读打开目录，避免 SQLite 与文件锁的反向等待。

原预算 HTTP 探针仍使用自行填写 FILTERED 的观察，被新门禁拒绝；已接入同一证据发布流程并携带执行 Token，正常系统时钟环境 43/43 检查通过。普通 URL fragment 与展示 URL 的处理也已分离：安全锚点保持动作和模型绑定，敏感 URL 拒绝，展示地址隐藏 fragment。敏感供应商元数据和动作语义在持久日志之前拒绝；晚于暂停到达的动作结果保持 UNKNOWN，不允许旧执行器发布当前证据。

影像格式／尺寸检查前置于任何工件发布，完整采集还须有最终脱敏视图，避免部分文件已提交就被当作完成。原始图像在底层传输也默认阻断，全灰 PNG不能支持坐标动作。早期失败的日志和报告保留，没有覆盖为成功；首轮沙箱监听限制不计作功能通过，最终统一验收在允许隔离本机监听的环境完成。

## 适用边界

本项提供证据字节完整性、过滤策略和消费资格，不实现 M1-15 的独立业务验证／成功聚合器，也不实现 M1-16 产品执行图。普通 Worker 仍无业务执行器，`task_execution_enabled=false`。

文本规则不能保证识别未知的任意秘密；不透明内容默认阻断，全灰副本不能证明原页面事实。正式网站写入、自动 OCR、局部图片解密／脱敏、完整恢复和结果页仍属于对应后续任务。

本次不重启用户既有服务、不推送 Git；现有 API／Worker 在用户后续启动时才加载 schema v13 和本项代码。清单、完成标记、源码快照和验收汇总已更新。
