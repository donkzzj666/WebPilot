## 交付

- 新增 `sessions` 模块，提供默认有界面的独立 Chromium、非持久 BrowserContext 和严格归属查询。Worker 持有管理器，启动时只初始化管理能力，首次创建会话才启动浏览器。
- 显式 v8 迁移新增会话、认证快照索引、会话事件三张表。`OPENING → OPEN → CLOSING → CLOSED` 与异常 `LOST` 分开，状态和事件同事务落库，历史不可删除或覆盖。
- 每个数据目录只允许一个管理器持有 OS 文件锁；最多四个存活上下文，创建中的上下文也占名额，不自动驱逐等待中的窗口。进程重启后把旧非终态记录标为 LOST，不重新连接并操作旧页面。
- 明确区分正常关闭、用户关闭最后一页、上下文关闭、页面崩溃、浏览器断连和管理器中断。取消与超时有界清理；不能证明资源已结束时保留占用并阻止继续分配。
- 显式保存认证快照，使用 AES-256-GCM 和独立 Keychain 服务保存随机密钥；站点、身份、环境和引用参与认证，目录 0700、密文文件 0600。SQLite 只保存范围、引用和摘要，明文只在会话模块内存中流转。
- 恢复 Cookie、localStorage 和 IndexedDB 时仍要求身份与业务重查；sessionStorage 不保存、不注入。丢失和新建均记录重查要求，不提供绕过核验的恢复执行入口。
- 锁定新增 `cryptography==50.0.1`、`cffi==2.1.1`、`pycparser==3.0`，保留其余依赖版本，更新构建、许可和依赖清单。API／前端健康信息更新到 M1-08，仍明确任务执行未启用。

内部接口、状态表和使用方式见[会话开发说明](../../development/browser-sessions.md)。

## 交付边界

- 当前提供 Worker 内部会话能力；登录窗口 API、身份核验、全局调度租约、网络边界、动作网关和完整执行循环分别由后续 M1-09／10／12／13／16 接入。健康检查仍为 `task_execution_enabled=false`。
- 重查标记和持久事件是后续模块必须消费的前提，本项未伪造身份核验结果。认证恢复不代表 DOM、页面执行栈、在途请求或完整浏览器内存恢复，也不重放上次点击。
- 认证读取受应用模块边界、文件权限和 OS 凭据设施限制；同一 OS 用户的任意恶意代码并非被进程沙箱隔离。当前真实验证平台为 macOS／Keychain，管理器使用 POSIX 文件锁，不声称已支持 Windows。
- OS 凭据调用在线程中执行，异步取消不能撤销底层调用；发布引用前故障可能留下未引用的密文和密钥，暂不猜测式删除。后续清理须先核对已提交引用。
- 测试浏览器仅连接不向上游转发的本机夹具代理；这是验收隔离，不代表 M1-12 产品网络策略已完成。正常业务站点、账号登录质量及真实业务执行不在本项验收范围内。
