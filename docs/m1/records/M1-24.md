## 交付与判定范围

`verify_fault_acceptance.py` 新增三组同一 Run 对账：暂停已提交后强杀 Worker；取消受理事务 COMMIT 前／后强杀 API。每组都先通过真实浏览器完成动作，再由新进程完成恢复／取消；核对原预算 ID、尝试与日扣、累计计数、原始工件、状态版本与持久事件。成功恢复域在新 Worker 活跃时拒绝旧资格，并在成功后损坏其实际原件；API／结果页须撤销完整成功展示，历史聚合保留。

故障汇总按固定顺序复跑 12 个子组：恢复、写入、控制、预算、调度、网关、API 防护、两种浏览器网络模式、证据、工作台、结果页，加上同 Run 对账共 13 组。恢复必须覆盖选定 15 域，写入必须覆盖七域及对应结果；工作台／结果页须有实际秘密扫描和非空工件哈希，不能仅接受 `passed=true`。

私有跨层数据和日志保存在 `.private/`，子探针输出保存在 `.owned/`，均为模式 0700；内层按自己的输出边界生成安全工件。外层汇总和全新安装公开导出排除两个目录及 `.security/`，最终私有清单只记录本地路径和 SHA。所有自有服务退出后才固定哈希；无法确认退出时判失败并暂缓哈希。首个错误与清理错误分开保留。

FR-01～03 按本轮实际执行报告判定；FR-03 仍为自有写入协议测试，真实 GitHub 适配属于 M2-07。FR-04/05 仅汇总 M1 已实现部分：真实人工交接／换账号或对象／完整到期、CI SHA／站点冷却业务、全等待组合及协调备份迁移仍待后续阶段。完整提示注入、监控水位／通知、基准恢复和 WebArena HAR 专项也未在本项虚标完成。
