# M1-17：两类检查点与只读崩溃恢复

状态：**VERIFIED**。完成日期：2026-10-01。M1 清单进度：**17/25**。

业务 SQLite 是任务、事件、步骤、证据、预算、身份和租约的权威来源；独立 AsyncSqliteSaver 只保存固定 Run/thread、图版本、状态版本和业务引用。新增 schema v16 的不可覆盖恢复记录及只读恢复导航记录，v1～v15 SQL 和 M1-16 源码快照保持原样。

重启后的 Run 先进入 RECONCILING。执行器核对冻结契约、图引用、真实业务事件、工件和当前租约，再复用存活上下文或重建丢失上下文，经受控观察查证当前账号、对象和版本。证明须绑定当前页面、会话、代号及原始证据字段位置，提交 COMPLETE 后才获得 RUNNING 资格。旧点击和模型输出不会重放，未决只读步骤保留原 INTENT／UNKNOWN，通过新观察追加查证引用后重新决策。

每次崩溃恢复以 Run／代号下的稳定 attempt 扣动作与恢复额度，重复入口不重复扣除；新观察、导航、截图和模型调用继续按原预算计量。已验收子目标从真实最新检查胶囊恢复，原失败和已扣预算不丢失。聚合器已提交终态而图库落后时，启动修复只同步图引用，不再次调用模型、浏览器或业务聚合器。

账号、对象、版本、事件和工件失配、未交还的人工控制权、未确认写入及预算不足都会持久阻塞。队列释放活跃槽并保留逻辑资源占用，避免反复调度阻塞任务；独立身份的其他任务仍可继续。认证只读恢复 API 可分页读取固定诊断和业务引用，不能清除阻塞，也不泄露账号、证据正文或执行 Token。

## 联调修复与适用范围

真实故障联调发现并修复：旧观察器的网络拦截影响新观察器；已完成只读动作缺少实际允许目标 URL；旧 INTENT 阻挡有当前证明的新动作；图进度落后于业务事件导致混用引用；前置等待失去控制权后的会话关闭竞态。另补齐缺版本观察后的同对象历史约束、首个图输入引用，以及终态预算失败后的人工窗口保护。恢复完成前后会再次检查证据、页面及资格，BLOCKED 不能通过更换图输入被清除。开发失败报告保持在本轮验收目录，不替代最终通过报告。

当前默认解析覆盖实际可见 JSON 的明确对象字段及已有场景结构，受信任适配器必须给出基于原始证据的字段绑定。普通 HTML、PDF、图像及其他站点的恢复适配仍需后续实现。当前闭环支持内部可信代码入队的只读 Run；M1-18 负责公开控制入口及可信解除流程，M1-23 负责外部写入 INTENT／UNKNOWN 的查证三分支。M1-17 保留未确认写入与隔离状态，不自动重试。
