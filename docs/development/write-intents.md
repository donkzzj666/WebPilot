# 写入意图与 UNKNOWN 查证

浏览器点击和本地数据库提交不能组成同一个事务。页面可能已经写入，而 Worker 在保存回执前退出。因此，浏览器返回成功不直接确认业务写入，重启也不能直接再点击一次。

## 从意图到查证

`gateway` 在派发前，用短事务保存意图、独立步骤、预算扣额和尝试关联；网络与浏览器操作都在事务外执行。`writes` 的稳定业务键由任务、身份、仓库、分支、基准 SHA、操作、文件集合和预期变化摘要生成，不包含 Run、epoch、页面快照或模型临时操作编号。同一任务的新 Run 沿用已登记的操作。

| 状态 | 含义 | 可以再次派发吗？ |
| --- | --- | --- |
| INTENT | 派发意图已保存，外部结果尚未确认 | 先查证 |
| UNKNOWN | 已中断、超时或无法判断实际结果 | 保持隔离，先查证 |
| CONFIRMED | 曾由可信证据确认预期变化已发生 | 取得当前有效证明后复用回执，不再写入 |
| NOT_APPLIED | 当前证据确认变化未发生，且前提一致 | 重新核对目标后，按剩余预算派发新的尝试 |

可信页面适配器只能通过内部 `WriteCheckSurface` 观察或执行受控 GET／HEAD。它返回有界 `WriteCheckCapture`，声明查证为 `APPLIED`、`NOT_APPLIED` 或 `UNKNOWN`。服务保存受限原件，并核对实际页面、会话、身份、租约、epoch、目标和原件哈希；字段失配、前提变化或证据不可用都不能成为重试许可。

`NOT_APPLIED` 证明只能由当前 Run／Worker／epoch 使用一次，有效时间为 60 秒。恢复查证到 RUNNING 的一次版本推进可以沿用证明；暂停、撤权、新 Run 或已消费的证明必须重新查证。再次派发前，可信授权器重新核对实际编辑目标与前提，并创建新的步骤和预算尝试。被强杀的旧尝试仍保留原始 INTENT／UNKNOWN 和扣额。

已确认的历史状态与回执不会被后续查询覆盖。当前页面改变、新 Run 或新的未知查询会使当前复用证明失效，须重新观察实际结果。结果聚合器只接受当前 Run 的有效原始查证证据；未决写入不能成为完整成功。

历史 CONFIRMED 缺少当前证明时，网关返回不派发的 UNKNOWN 查证入口及原操作编号，图随即查询实际结果；账本仍保留历史 CONFIRMED。旧 epoch 的 INTENT 步骤经当前执行资格下的 APPLIED 原件确认后，可以作为已解决历史保留，允许后续不同写入；当前 epoch 的在途步骤仍阻塞。历史步骤的解决不因换页或超过缓存期限撤销，当前操作的回执复用仍必须满足前述当前证明要求。

## 重启、取消和重跑

Worker 重启使用新的执行资格，先通过只读查证处理未确认写入，再进入 M1-17 的业务／图检查点恢复。正常网关始终拒绝未决写入；查证持有资源租约不等于获得写入权限。

取消停止新动作并保留已发出的意图、外部变化和未决写入的资源隔离，不发送回滚请求。终态任务的重跑若保留相同冻结契约和已登记协议，会先创建显式 RECONCILING Run；只有原会话已 CLOSED／LOST、无人工持有和活跃执行器时，才允许转移逻辑租约用于查证。旧版、混合未决记录或契约变化继续保持阻塞。人工控制、预算到期、查证无法判断时，不自动重试。

## 文件和接口

- `backend/webagent/writes/models.py`：稳定键与严格事实模型。
- `backend/webagent/writes/store.py`：意图、证明、逐次派发和历史关联。
- `backend/webagent/writes/service.py`：内部只读查证面和受限证据保存。
- `backend/webagent/db/sql/0018_write_protocol.sql`：显式 schema v18 迁移，保留 v1～v17。
- `GET /v1/runs/{run_id}/write-intents?after=0&limit=100`：认证、分页的状态诊断；不返回回执正文、原件、凭据或执行 Token，不接受确认或执行命令。

默认 Worker 未安装真实业务写入适配器。M1-23 在隔离测试站验证协议；真实 GitHub 页面适配与业务闭环属于后续任务。图执行器只能由可信本地代码显式安装协议网关，API、网页和模型不能提交适配器或可执行代码。

组件测试覆盖协议、网关、队列、控制、图和聚合边界。`scripts/verification/verify_writes.py` 使用自有 HTTP 测试站、Chromium、业务 SQLite、独立 AsyncSqliteSaver 和真实进程强杀；`scripts/check.sh` 统一运行。验收结果见 [M1-23 记录](../m1/records/M1-23.md)。
