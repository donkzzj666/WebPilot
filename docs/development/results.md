# 结果与证据页面

在任务入口选择任务，再进入「结果与证据」。页面展示当前运行的持久结果，也可以逐条查看历史运行；重跑不会覆盖旧运行。`task` 保留任务选择，`result_run` 保留结果页所选运行，页面刷新后可继续核查。

## 怎样读结果

- **业务结果**来自运行时验证器和业务聚合器保存的结论，包括成功、部分完成、失败、取消。没有聚合记录时明确显示没有结果，不从运行状态推断交付成功。
- **当前可核查性**另外检查证据文件、展示副本和整个任务的写入账本。历史业务结果为成功，仍可能因证据丢失、损坏、过期或未决写入而不能显示「完整成功」。刷新失败时也不能继续使用旧的完整成功提示。
- **字段与验收条件**分别展示 PASS（通过）、FAIL（不通过）、INSUFFICIENT（证据不足）、CONFLICT（证据冲突）。字段通过保存的 RFC 6901 路径读取实际业务值，区分缺失与 `null`；核查诊断折叠保留，对应证据可直接打开。
- **覆盖范围**包含搜索来源、查询、截止时间、读取页面数、未读候选、缺口和未解决事项。人工参与次数单独显示，不把有人协助的成功称为自主完成。
- **副作用**区分当次聚合时记录的结论和任务全部运行当前的写入意图。INTENT、CONFIRMED、NOT_APPLIED、UNKNOWN 均可见；失败和取消不表示外部写入已回滚。

证据按钮只读取服务允许的过滤文本、差异或中性 PNG 副本。中性图片是完全遮蔽的展示占位，不能用于证明网页视觉内容；原始网页、HTML、私有工件路径及未过滤图片不会直接嵌入页面。

## 接口与代码

`GET /v1/tasks/{task_id}/results?run_id=<可选>&before=<可选>&limit=20` 提供结果页一致快照。省略 `run_id` 时选择当前运行；指定的运行必须属于任务。`before` 为十进制字符串游标，`limit` 为 1–100。未知、重复或不合法查询参数被拒绝。接口沿用本机认证、Origin 防护和 `Cache-Control: no-store`。

| 位置 | 职责 |
| --- | --- |
| `backend/webagent/results/routes.py` | 参数边界和只读结果路由 |
| `backend/webagent/results/store.py` | 单事务结果、历史、证据与副作用投影 |
| `frontend/src/results/ResultsPage.tsx` | 所选运行、字段证据、覆盖范围、历史与副作用界面 |
| `frontend/src/results/contracts.ts` | 响应类型、对象绑定和成功前提检查 |
| `frontend/src/results/fields.ts` | 只读取自有属性的字段路径解析，阻止原型和访问器遍历 |
| `frontend/src/results/client.ts` | 认证 GET、响应上限与证据 SHA-256 校验 |
| `tests/storage/test_results.py` | 数据完整性、只读性、历史分页及失效证据回归 |
| `scripts/verification/verify_results.py` | 隔离 API／Vite／Chromium 实际页面验收 |

投影使用 SQLite `mode=ro`、`query_only` 和一次事务，限定 SQL 工作量、历史页、证据引用、物理读取总量及写入记录数。读取不会建库、迁移、结算预算、领取执行或触发恢复。结果 JSON、验证记录、冻结契约、状态版本及所选运行都须绑定一致；损坏时返回安全的不可用状态，保留原记录。

证据索引不是完整性证明。投影用禁止跟随符号链接的受控文件读取校验实际长度和哈希，追溯原始工件及过滤副本关系，不调用会写可用性事件的普通 EvidenceStore 读取入口。浏览器再通过既有 `/v1/evidence/{id}` 与 `/content` 认证读取展示副本，独立检查运行、快照、派生关系、长度、MIME 和 SHA-256。普通证据读取仍沿用已有的可用性事件行为。

加载更早历史时也会重新应用该响应中的证据及副作用状态；查询失败、版本变化或证据内容读取失败会撤销本页完整成功展示。写入权限依据损坏或缺失时显示「暂不可核查」，不凭空认定关键违规，也不据此宣告成功。

## 验证与范围

单项验收：`.venv/bin/python scripts/verification/verify_results.py --output-dir <全新目录>`。完整回归：`./scripts/check.sh --headed`。全新安装回归：`.venv/bin/python scripts/verification/verify_clean_install.py`。输出目录不能覆盖，失败也保留报告。

验收在隔离数据域中使用自有 HTTP 来源、真实证据入库和真实验证／聚合服务，再经实际页面读取。运行准备、人工次数、取消和副作用样例中使用的账本夹具在报告中注明。此项验证页面及其读取边界；不替代 M1-25 的真实公开只读业务闭环，也不执行真实 GitHub 写入。
