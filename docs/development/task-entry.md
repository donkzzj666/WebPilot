# 任务入口、模型配置与账号准备

M1-20 将既有任务编译、配置快照和登录身份 API 接入本机页面。用户可以输入目标、明确来源和权限，查看服务实际保存的契约，集中补充缺失信息，并在重载后继续查询历史任务。**创建、补参和修订只做任务准备，不创建 Run、不入队，也不表示业务执行成功。** M1-21 的[执行工作台](workbench.md)接入明确启动、实时进度和运行控制；结果页仍待 M1-22，现有公开运行控制 API 见[运行控制说明](run-controls.md)。最终验收范围见 [M1-20 记录](../m1/records/M1-20.md)。

## 从页面开始

按[项目首页](../../README.md)分别启动 API、Worker 和前端，三个进程使用相同的 `WEBAGENT_DATA_DIR` 与 API 端口。打开 `http://127.0.0.1:5173`，顶部导航可到达“任务入口”“执行进度”“模型配置”和“账号准备”。页面从 `/api/` 受限 Vite 代理调用本机 API，用户不需要复制 Bearer 令牌。

“API 已连接”只说明当前 API 与本机存储可读取。页面另行查询模型就绪状态和 Worker 的账号元数据：模型未配置会阻止自然语言编译；账号服务不可用会明确显示未知状态，公开只读任务仍可不指定账号。身份准备成功、契约 READY 和运行成功是三种不同结论。

填写任务时先描述对象、时间和预期结果，例如“读取 ACME 的 2025 年度财报营收，以 USD 美元计量”。每个来源都需明确来源标识、站点标识、HTTP(S) origin、允许路径前缀和起始 URL，并勾选访问授权。添加来源或改变路径后需要重新确认。输入来源不是网络放行规则：实际执行仍受[浏览器网络边界](network-security.md)限制，不能访问本机控制 API、私有网络或未登记的评测端点。

任务默认“只读浏览与读取”。代码修复需要单独选择仓库写入，填写仓库、基线 SHA、工作分支、明确文件白名单、保护规则、必需检查、独立规则与逐项允许动作，另行勾选写入授权并选择匹配身份。自然语言中的“修改”不会授予写入；这项界面也不安装真实网站写入适配器。现有写入协议与执行接入边界见[写入意图说明](write-intents.md)。

点击“提交任务”使用 `compiler_mode: natural_language`：生产模型适配器提取业务建议，程序核验用户输入依据、来源、权限和验收规则后保存。模型配置缺失或凭据不可读取时先完成配置，或者点击“刷新模型就绪状态”核对。编译可能产生模型调用；保存模型设置和查询任务列表不会调用模型。

## 任务卡、缺参与修订

任务列表和详情由本机 SQLite 持久记录读取，页面重载会重新请求列表及所选任务。URL 的 `task` 参数只保存任务 ID。详情展示准备状态、实际修订、来源及起始页面、允许动作、账号绑定、业务参数、时间口径、预期输出和验收条件。当前修订未完成时，已有契约会明确标注为上一个保存版本。

缺失字段集中显示在一处。补参只发送服务本次列出的字段，不提供任意 JSON 递归修改；新增来源、写权限或身份若被明确列为缺参，还需各自的授权或账号选择。提交前需勾选“我已核对信息，仅补充本次列出的必需字段”。已有来源与动作不会因填写企业、报告年份等参数而扩大。

| 情况 | 页面行为 |
| --- | --- |
| 422 参数或范围不合法 | 显示固定安全提示，保留非秘密草稿；修正后明确提交新的内容 |
| 修改已知任务时的 409 版本或状态冲突 | 读取最新任务、保留输入并锁住修改；用户核对新版本后点击“我已核对最新任务”，重新勾选提交确认 |
| 请求结果未知或网络中断 | 保留原输入与组件内的幂等请求信息；先读取原任务或在当前页面以相同请求查询，不能把未知结果当作失败后新建 |
| 修改模型配置时发生 409 | 保留非秘密配置草稿，禁止覆盖；“重新载入最新配置”显式读取最新版本后再填写、确认 |

POST 任务、补参和修订使用 `Idempotency-Key`，相同请求可重放原收据，改变内容会生成新的键。键和待提交正文仅保存在组件内存，页面重载不会恢复这些未提交内容；不要把重载后的新建请求当作原请求的幂等重试。服务器持久对象和收据仍保留，已知任务 ID 可重新读取。

“修改任务”提交完整替换修订。修订从只读、未绑定账号、未勾选访问及写入授权开始，用户必须重新核对完整内容；它不静默继承旧权限，也不自动保留原来人工补充的业务字段。请在新的指令中重新说明对象与时间，或按新的缺参提示补充。“新建任务”显式重置可见输入与授权，历史任务保持可查询。

## 持久列表接口

`GET /v1/tasks?limit=20` 返回 `tasks`、`next_cursor` 和 `as_of`。每项包含任务基础字段、用户原指令、当前准备修订、当前 Run 状态和最近准备更新时间。列表不返回完整契约、模型上下文、密钥、图库、证据原件或登录认证内容。

`limit` 为 1–100，默认 20。下一页将响应中的 `next_cursor` 原样作为 `before`：它是正十进制字符串，范围不超过 SQLite 64 位正整数，不能先转成 JavaScript `Number`。服务按不可变插入顺序降序查询 `rowid < before`；后续新任务不会挤入已读页，但现有任务的状态仍可更新，每页是独立一致快照。刷新列表从第一页重新读取。

列表使用 `mode=ro`、`query_only`、有界 SQLite 工作量和单次读事务。它不建库、不迁移、不修复队列、不调用模型；缺库或读故障返回安全的 503，非法、重复或未知分页参数返回 422。与详情和配置一样，接口要求本机认证及来源边界，响应 `Cache-Control: no-store`。

## 模型配置和数据发送

页面仅列出后端支持的 DeepSeek／deepseek-flash 与官方 HTTPS 服务地址，不提供可将凭据转发到任意主机的自定义地址。用户可调整 token 上限、连接／读取／总超时，以及可选 USD／CNY 静态 token 单价和缓存命中输入单价；价格版本由内容摘要生成，无价格或无完整用量时费用保持未知，不能显示为零。保存新版本影响之后的 Run，历史 Run 继续使用冻结的配置、价目与凭据引用。

API Key 输入框之前明确说明：所选提供商可能接收**任务正文、经过过滤的任务相关网页内容和选中的必要截图**，并展示后端当前披露条目。用户必须明确确认发送范围才能保存设置。任务编译会发送指令和必要参数；登录准备不向模型发送密码、验证码、登录页面或截图。

浏览器中的 API Key 输入只留在组件内存，用密码框输入，不回填；构造保存请求后立即清空，提交结束再次清空，不存入 localStorage、sessionStorage、URL、SQLite 普通配置或日志。留空省略 `api_key`，沿用已有凭据；生产密钥保存在 macOS Keychain，不提供明文文件回退。详细发布事务、轮换和冻结快照见[配置与密钥说明](settings.md)，费用规则见[观测说明](observability.md)。

“本机模型配置就绪”仅证明配置与本机凭据可读取。保存配置不请求提供商，不能证明 Key 有效、余额充足或模型可用。凭据库锁定、缺失、拒绝访问等原因独立展示，先处理原因再重新载入。

## 账号就绪和登录准备

账号准备读取 Worker 的站点目录及身份记录。创建时只提交受支持站点、预期账号和可选历史身份；密码和验证码仅在 Worker 打开的受管站点窗口内输入。返回了 HTTP 201 或登录窗口已打开，都不表示身份已核实。

完成站点登录后点击“确认页面身份”。客户端先 GET 当前持久状态和版本，变化时只更新展示，要求用户重新核对后再点击；不静默重试确认或关闭。实际确认仍由固定站点适配器检查，并经过认证导出前后的两次身份核验后原子发布。错账号保持 `NEEDS_LOGIN`，明确提示切换账号，不发布可用身份。状态冲突、超时或未知变更结果后需要先“查询登录准备”，再继续操作。

服务器已确认的登录准备 ID 可保存在 URL 的 `login_session` 参数，重载后真实 GET 恢复该记录。历史身份列表显示站点、realm、账号、状态及版本，始终说明每个 Run 还须核对当前身份和业务条件；不展示 cookie、认证密文引用或密钥。

公网任务只可选择 `public` realm、VERIFIED 且与全部来源的站点及 origin 匹配的身份。身份不会自动选取、替换或跨站复用。`webarena` 身份可以在账号准备区显示，但不能作为公网任务的身份授权。验收中的 owned 合成登录站使用真实 `webarena` realm，证明的是登录协议和 UI 状态，不是已登录真实 GitHub，也不改变生产站点目录或公网网络规则。详情见[身份说明](identities.md)。
